## Scope

Move the registry, messages, transports, harness adapters, inbox review, request ledger and
filesystem work protocol, with their CLI commands, docs and tests, out of delivery-kit 4.7.0 into
coordination-kit 1.0.0, and add `work check` and `work report`.

## Criteria

- Every on-disk format stays byte-compatible with delivery-kit 4.7.0.
- The commands keep their verbs, options, JSON output and exit codes under `coordination-kit`.
- `--root` and `DELIVERY_KIT_ROOT` keep working; `COORDINATION_KIT_ROOT` takes precedence.
- delivery-kit depends on this kit through a one-way seam; this kit never imports delivery-kit.
- `work check` and `work report` are unit-tested against a copy of delivery-kit's own docs.

## Decisions

- Protocol work reference `dk-coordination-split`.
- The runner keeps cadence; `deliverScheduledReview` composes and delivers the review, and the
  event outbox lives here while delivery-kit adds its commit tracking under the outbox lock.
- Shared utilities are exported once from `build/shared`; the API bundles share chunks so one
  module instance serves every subpath.
- Work plan `path` and `commit` fields are left to [ck-0007](ck-0007.md).

## Outcome

Delivered in 1.0.0 with the seven `build/` subpaths and the `coordination-kit` CLI. Runner-driven
review and event contract cases stay with delivery-kit, which runs them through the seam.
