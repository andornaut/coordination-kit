## Scope

Keep message status, dispatch and the channel consumer's guard bounded as the message store grows.

Baseline on delivery-kit 4.6.2 at about 2650 records (73 MB): `protocol message-receipt` about 50 s
per receipt, `message status --recipient` several minutes, `message status --id` and
`message reconcile` about 1 s.

## Criteria

- The records read per operation do not grow with the total number of stored messages, including `protocol message-receipt`.
- Existing message records remain readable byte for byte.
- Status output and exit codes do not change.

## Decisions

- Lookup hints, not a record change: `message-index/` beside the records directory holds empty
  marker files keyed by the SHA-256 of a recipient role or attempt request ID and named by the
  record file. It sits outside the migrated record inventory and holds no message data.
- A save writes the hints for its record's immutable recipient and append-only request IDs
  before the record, idempotently and without a new lock, so earlier writers and crashes leave
  records uncovered rather than misindexed. Record bytes and the on-disk format are unchanged.
- Readers verify each hinted record and read every record without a recipient hint, found by
  comparing directory listings. A request miss falls back to one full scan, which restores the
  hints. Removing `message-index/` rebuilds it. No compaction.
- Status by ID, status by recipient, the channel consumer and boundary accounting capture read
  only their selection. The review inventory and `retire-spool` still scan every record, as
  their inventory and exactly-one rules require.
- Each status read shares one protocol read view, checks the generation selection at view entry
  and exit, and verifies each original once. A protocol inbox verifies only originals addressed
  to its role. Journal replay projects objects incrementally and sorts once per replay.

## Outcome

Delivered. On a synthetic store of 2700 records and 2710 journal events, then grown to 5400
records addressed to other roles:

| Operation                  | Before, 2700 | Before, 5400 | After, 2700 | After, 5400 |
| -------------------------- | ------------ | ------------ | ----------- | ----------- |
| `message status --id`      | 4.0 s        | 16.4 s       | 0.19 s      | 0.33 s      |
| `status --recipient`       | 5.2 s        | 15.5 s       | 0.27 s      | 0.58 s      |
| `message reconcile`        | 3.0 s        | 16.9 s       | 0.15 s      | 0.34 s      |
| `protocol message-receipt` | 19.1 s       | 51.7 s       | 2.7 s       | 4.6 s       |

Message records read per receipt went from every record (2700, then 5400) to the role's own
505 in both, and legacy artifacts from 17213 and 33415 to 1520. Status output and exit codes
are unchanged. Journal events read still grow with the involved roles' journals, because every
protocol read replays and verifies a whole role journal; bounding that needs verified journal
checkpoints, a separate item.
