## Scope

`inbox snapshot` and `inbox ack` accept a Claude worker recipient with verified lineage to one registered parent, as they do for Codex workers.

## Criteria

- Lineage is verified against the exact parent before capture and again before acknowledgement.
- A wrong or changed parent fails closed and preserves originals.
- Unavailable lineage stays unknown and is never clearance.

## Decisions

- Cancelled (user, 2026-11-18): no lineage source a Claude worker cannot forge exists. `claude agents
--json` lists only top-level sessions, and subagent metadata files are writable by the worker's
  own user. A parent-attested binding would be attribution, not verification.

## Outcome

Not implemented. Claude workers stay parent-owned, and their lineage is reported as unknown. A new
item is opened if Claude Code exposes subagent lineage through a live harness interface.
