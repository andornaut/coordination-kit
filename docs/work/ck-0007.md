## Scope

Work plan artifacts keep their hash and gain optional `path` and `commit` fields that point at the repository work file, with no schema generation change.

## Criteria

- Publications without the fields remain valid and readable.
- `work report` joins a publication to its work file by those fields as well as by ID.
- The fields are references only; they grant no approval.

## Decisions

- `path` and `commit` sit on `definition.plan` beside `hash` and `size`, so a publication carries
  them in its definition and its hash without a schema generation change.
- A path is repository-relative with no dot or empty segment, and a `commit` requires a `path`;
  both are references only, never compared with the plan bytes or the repository.
- `work report` keys joins by work-file path and reports `joinedBy` and the plan reference beside
  the existing fields.

## Outcome

A work publication can name the work file it implements, and `work report` lists it under that
file even when its definition ID differs. Older publications read and join as before.
