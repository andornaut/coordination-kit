## Scope

`message status --recipient chibis-way-home/gameplay` fails with `binding-conflict` while `message status --id` works for the same messages. Find the record that triggers it and make recipient status report every message.

## Criteria

- A contract case reproduces the failure from a fixture shaped like the failing store.
- Recipient status lists every message for the recipient; a record it cannot read is reported per message, not as a failure of the whole command.
- Per-ID status, reconcile and their exit codes do not change.

## Decisions

- No single record triggers the failure. The listing re-read each scanned record outside the
  protocol read view, so it ran for minutes, and a concurrent reconcile of any listed record in
  that window failed the whole command with `binding-conflict`.
- Recipient status is a point-in-time snapshot: views come from the scanned records, and the scan
  and its protocol lookups share one read view. Per-ID status keeps its re-read check. An
  unreadable or misbound record still fails the listing, as the scan's binding checks require.

## Outcome

Delivered in 1.0.2: recipient status lists every message at its snapshot revision and reads each
protocol role state once per listing. A unit case reconciles a listed record from a separate CLI
process between the scan and the views; it fails with `binding-conflict` before the fix.
