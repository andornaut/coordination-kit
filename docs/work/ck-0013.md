## Scope

Automatic capture names an intake offer by its whole content, including a source reference that
contains the boundary phase. The same requests captured again under another phase, or with
coverage that adds nothing new, become a new offer and a new intake reference, which enrollment
reports as uncovered until the role lists it. Make a restated capture produce no new reference.

## Criteria

- Capturing the same requests and coverage under another phase creates no new intake reference.
- A capture with any new request or any new coverage gap still creates a reference that the
  enrollment report shows as uncovered for its role.
- Existing intake records and enrollment receipts stay readable, and adoption of roles enrolled
  before the change does not change.

## Decisions

- Drop the phase from the capture source and skip an offer whose every request and coverage entry
  already equals one pending for the same role or held by the current ledger projection. Keying
  references by content instead would change the enrollment reference keys that existing receipts
  and anchors list, so the content-addressed offer ID stays the reference key.
- Compare whole entries, never request IDs alone, so a changed coverage window or gap is new.
  Any unreadable journal or intake directory keeps the offer, so retention never depends on dedupe.

## Outcome

`IntakeStore.restated` and automatic capture add no offer for a restated capture; new requests
and coverage still produce an uncovered intake reference. Offer and receipt formats are
unchanged, and offers retained under the old source keep their IDs and still match restatements.
