## Scope

The finish, handoff and cleanup boundaries accept work whose linked requests are completed,
reviewed and owner-attested, but the work report drops completed requests from authorization, so
such work reads as `unknownRetained` and its role as `partial`. Make the report agree with the
boundaries for closed historical work.

## Criteria

- A work whose linked requests are all completed, reviewed, owner-attested and in scope, with every
  criterion passed and no guard, is not reported as `unknownRetained`.
- A cancelled or superseded request, an unsatisfied criterion or a guard still reports the work as
  `unknownRetained`.
- `before-work` and `worker-start` still refuse completed requests with `approved-work-required`.
- The boundaries and the report use one shared evaluation.

## Decisions

- `WorkStore` owns the closed-history test as `WorkEvaluation.historicallyClosed`, and the
  boundaries read that field instead of a second copy, so the report and the boundaries cannot
  diverge.
- `authorization` is unchanged, so completion never renews execution authority at `before-work`
  or `worker-start`.
- Explicit `retention` keeps closed work in `unknownRetained`, because it is an owner's declared
  retention rather than a missing authority.

## Outcome

The work report in `protocol boundary` output no longer lists completed, reviewed, in-scope work
with passed criteria as `unknownRetained`, and its role reads `available` when nothing else is
retained or unavailable.
