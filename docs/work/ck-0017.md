## Scope

Implement the coordination-kit part of Phase 2 in the [simplification design](../design/simplification.md#phase-2-one-store-and-one-message-path): the SQLite store, `msg send|done|retain|status|history`, `inbox`, wake adapters, stored briefs and runner events, `events ingest`, and `store import|export` with the cutover and rollback procedure.

## Criteria

- Every send is durable before any native action, and recipients pull.
- A message closes with one write.
- Import keeps every original ID, body hash, link and evidence, with uncertain deliveries flagged `unconfirmed`.
- The Phase 2 exit criteria in the design hold.

## Decisions

- The store is `<stateRoot>/coordination.db`, or `var/coordination.db` without an active work
  protocol, beside the wake files. Each command is one `BEGIN IMMEDIATE` transaction; no native
  call runs inside one.
- Projections are tables with one applier per event kind. A kind without an applier is still
  chained, so the later Phase 2 work adds its projections and picks up existing events on rebuild.
- The fence refuses `caller-ambiguous` when both harness variables bind a role, as in a session
  started from another harness's shell; `--native-id` settles it. Reads and the import dry run
  take no caller.
- `msg send` output carries only the wake status, never harness detail, so both adapters print the
  same JSON. A repeated send of the same original retries only the wake.
- A guard refusal leaves no outstanding wake and the next send checks again, since nothing native
  happened. Accepted, failed and ambiguous wakes stay outstanding until the recipient's pull or
  `rearmWake` from the review.
- The Codex wake uses the existing guarded queue path unchanged, so it also requires the
  recipient-bound decision marker before the native question check.
- Import maps `held` to `retained` (it carries a retention) and `parent-required` to `delivered`
  (the recipient role's conversation accepted it). The state-root copy of an ID wins over the
  pre-activation copy. Legacy close times are unknown, so `closedAt` is null.
- Closing or retaining a message still `sent` also sets its delivery time, since the recipient
  acted on it. Bodies over 1 MiB are refused.
- `inbox` alone is the store read; `inbox snapshot` and `inbox ack` keep their meaning. Help shows
  positional IDs as upper-case tokens.
- On a copy of the live legacy stores the dry run mapped 2680 records (1889 handled, 760
  superseded, 30 retained, 1 retained unconfirmed) and found the 2638 pre-activation records to be
  duplicates, 144 of them older snapshots. The synthetic 30,000-message store measured p95 2.9 ms
  for send, 0.7 ms for inbox and 0.6 ms for done in process.
