## Scope

Implement the coordination-kit part of Phase 3 in the [simplification design](../design/simplification.md#phase-3-work-decisions-questions-and-holds): `work`, `question`, `hold`, `decision` and `graph` commands, and the decision record format in work files.

## Criteria

- Question and hold writes require the owning role's binding.
- `question answer` records the decision in the store and the work file.
- `graph why` answers from git plus the derived index.
- The Phase 3 exit criteria in the design hold.

## Decisions

- D1 (coordination-kit, 2026-11-19): Work records are keyed by repository name and work ID; only
  the item's owner (front-matter `owner`, the repository's only role, or a game's design-area role
  then Tech) may write.
- D2 (coordination-kit, 2026-11-19): `work start` reads the work file from local `main` and asks a
  hold port; until the hold records ship, imported holds are the only covering holds.
- D3 (coordination-kit, 2026-11-19): The graph index is a derived cache outside the projections,
  rebuilt from Git and the store; queries build live without it.
- D4 (coordination-kit, 2026-11-19): `status` prefers store stage evidence per fact and adds fields
  only.
- D5 (coordination-kit, 2026-11-19): Approval-ledger holds import as `hold.imported` events with
  their recorded owner, or none; import never releases a hold or creates a work file.
- D6 (coordination-kit, 2026-11-19): Question IDs default to `q-<role>-<n>` with `/` in a game
  role written as `-`, numbered one above the highest such ID in the store; a retry that must not
  open a second question passes `--id`.
- D7 (coordination-kit, 2026-11-19): `question answer` checks the main checkout (on `main`), the
  work file and its Decisions section before the store write, then writes the store row and
  appends the line, unstaged; a repeated answer writes a missing line.
- D8 (coordination-kit, 2026-11-19): Decision numbers are one above the highest in the store and
  in the work file; the line's date is the UTC date of the decision time.
- D9 (coordination-kit, 2026-11-19): Decision text refuses secret shapes, home-directory paths,
  UUIDs and the local host name, since it lands in a public work file.
- D10 (coordination-kit, 2026-11-19): The wake guard withholds wakes for a pending question or an
  active `role` hold only; answer, cancel and release attempt one guarded wake for the owner.
- D11 (coordination-kit, 2026-11-19): Hold IDs are never reused, even after release.
- D12 (coordination-kit, 2026-11-19; supersedes D2): `work start` and `work show` read the hold
  records: active holds scoped to the item, its owner role or its game, including imported ones
  that keep their recorded owner; graph and `work check --decisions` read the decision and
  question records through the store API.
