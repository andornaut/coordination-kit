## Scope

Implement the coordination-kit part of Phase 3 in the [simplification design](../design/simplification.md#phase-3-work-decisions-questions-and-holds): `work`, `question`, `hold`, `decision` and `graph` commands, and the decision record format in work files.

## Criteria

- Question and hold writes require the owning role's binding.
- `question answer` records the decision in the store and the work file.
- `graph why` answers from git plus the derived index.
- The Phase 3 exit criteria in the design hold.

## Decisions

- Question IDs default to `q-<role>-<n>` with `/` in a game role written as `-`, numbered one above
  the highest such ID in the store; a retry that must not open a second question passes `--id`.
- `question answer` checks the main checkout (on `main`), the work file and its Decisions section
  before the store write, then writes the store row and appends the line, unstaged. A repeated
  answer writes a missing line, so the store stays the source a failed file write is repaired from.
- Decision numbers are one above the highest in the store and in the work file; the line's date is
  the UTC date of the decision time.
- Decision text refuses secret shapes, home-directory paths, UUIDs and the local host name, since
  it lands in a public work file.
- The wake guard withholds wakes for a pending question or an active `role` hold only; work and
  game holds do not. Answer, cancel and release attempt one guarded wake for the owner.
- Hold IDs are never reused, even after release.
