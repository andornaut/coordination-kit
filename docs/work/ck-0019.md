## Scope

Implement the coordination-kit part of Phase 4 in the [simplification design](../design/simplification.md#phase-4-thin-protocol-and-retirement): remove epochs, claims, enrollment, adoption, coverage, intake, the request ledger and protocol journals, and add `session start`. This also retires the protocol journal replay cost left open by ck-0004.

It also carries the store side of the three-mode harness handoff (prepare, send, complete): a handoff record with `handoff open`, `handoff ready`, `handoff active`, `handoff state` and `handoff show`.

## Criteria

- The legacy state is archived and readable with the archived release.
- No command takes a hand-built input file.
- `session start` prints the role's identity, binding, checkpoint path and counts of pending
  questions, holds and inbox items, so no separate orientation packet is needed.
- `handoff open --scope ROLE...|all --to claude|codex` and `handoff state
prepared|sent|completed|cancelled` are coordinator-only; `handoff ready` and `handoff active` are
  each role for itself through the registry fence; `handoff show` reports the record and per-role
  ready and active times.
- Prepare sets a role-scope hold per role that complete releases after the role's `session
start`; complete runs `harness select` before the target roles' `session start`.
- The Phase 4 exit check is a real round trip of one kit from Claude to Codex and back, when Codex
  quota exists.
- The Phase 4 exit criteria in the design hold.

## Decisions

- Handoff scope added (user, 2026-11-19, three-mode harness handoff with Phase 4 and 5).
- `store retire` is the one migration: open ledger requests become `request.imported` records
  that their owners map to work files or close with `request close`; closed requests stay in the
  archive; pending intake offers are dropped; originals stay in place.
- The archive is one tar.gz written by the system `tar`, with a manifest naming the 2.1.2 release
  to read it with.
- `var/work-protocol.json` is reduced to `stateRoot` (schema 2); the 2.1 shape is still read.
- `status` moves to schema 2 and reads imported requests from the store.
- `question open --options-file` becomes repeated `--option LABEL`, so no command takes a
  hand-built input file.
- `store cutover` and `store import --from-legacy` go with the legacy message store.
- `session start` prints JSON only; there is no text form (coordinator, 2026-11-19).
- `handoff active` releases the role's own handoff hold, and `completed` requires every role
  active, so complete releases each hold after that role's `session start`.
- A handoff scope moves from one harness to the other: `all` takes the roles not yet on the
  target, and a named role already on it is refused.

## Outcome

Shipped in coordination-kit 3.0.0. The protocol, request ledger, legacy message store and their
commands are removed; `store retire` archives the legacy state and imports open requests, which
owners close with `request close` or map to work files. `var/work-protocol.json` names only the
state root. `session start` prints a role's binding, checkpoint and open counts, and the
`handoff` verbs keep the store record of a harness handoff with per-role holds. The real kit
round trip from Claude to Codex and back remains the Phase 4 exit check, run when Codex quota
exists.
