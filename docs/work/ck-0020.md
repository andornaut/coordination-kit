## Scope

A read-only `coordination-kit status` over every registered repository joins work-file front
matter, live protocol state, linked ledger requests and delivery evidence (the first commit on
`main` citing the work ID, whether `origin/main` contains it, and the first runner COMPLETE event
covering it) into one derived status per item. The work-file convention gains `proposed` and
`declined`, so every user request has a work file.

## Criteria

- Each item reports one of requested, proposed, approved, in-progress, landed, deployed, done,
  declined, cancelled or superseded (with the replacement ID); blocked items report the blocker
  and owner when known.
- Filters: `--scope`, `--since`, repeatable `--state` and `--audit` for user-originated items
  with their evidence; JSON output by default and a `--format markdown` digest per repository.
- `work check` accepts `proposed` and `declined`.
- The command writes nothing and performs no network access.
