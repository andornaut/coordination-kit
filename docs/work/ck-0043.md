A Claude `/clear` gives the session a new conversation ID, and the role is caller-unbound until
the coordinator rebinds it. `session start` rebinds a Claude role when the caller's transcript
proves the rotation, and refuses otherwise with the existing refusals.

- Trigger: the fence refuses `caller-unbound`, the native ID comes from `CLAUDE_CODE_SESSION_ID`
  (not `--native-id`), and exactly one transcript `<projects>/*/<id>.jsonl` exists, where
  `<projects>` is `$CLAUDE_CONFIG_DIR/projects` or `~/.claude/projects`.
- Proof: the transcript header holds exactly one `derived-from` record with one
  `claude_code_session` entry and `via` `clear`. Its ID equals the current effective Claude
  binding of exactly one role. That role's phase is not `held` or `source-held`, and it has no
  open handoff.
- Write: replace that role's Claude conversation under the registry revision just read; a
  revision conflict refuses. Then run the normal session start, whose output names the rotation.
- Codex and every other verb are unchanged.

Source request: Game Coordinator, after six `/clear` rebinds in one evening.
