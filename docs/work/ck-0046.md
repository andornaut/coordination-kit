A work item can be recorded ready and then superseded or cancelled in its work file. `work finish`
refuses it with `work-not-done`, so the item stays ready in the store and every review lists it.

- `work finish` accepts a work file whose status is `done`, `superseded` or `cancelled`.
- A `superseded` item finishes only when a work file in the same repository names it in
  `supersedes`; the finish record cites that successor. Without one it refuses.
- The store record becomes finished and records the work file status, so the review and status
  drop it with no work-file reads and no new verb.

Source request: Game Coordinator, for a superseded ready item that every review listed.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-superseded-ready): work finish accepts superseded/cancelled (Recommended)

## Outcome

`work finish` accepts a work file that is `done`, `superseded` or `cancelled` on `main`. A
superseded item needs a work file on `main` whose `supersedes` names it (`successor-missing`
otherwise). The `work.finished` payload adds `status`, and `successors` for a superseded item; a
done payload is unchanged. Records expose `finishedStatus` and `successors`, and a finished record
leaves the review's ready handoffs and the open items of `status`. Ships in 6.1.0.
