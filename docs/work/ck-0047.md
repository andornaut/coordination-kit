Restructure the source without changing behaviour: clean module interfaces with no import
cycles, encapsulated internals, simpler code and pure functions where possible, with I/O at the
edges.

- The CLI, its JSON output and exit codes, on-disk and store formats, and the public build API
  subpaths keep their contracts.
- The dependency graph has no cycles, and a check keeps it that way.

Source request: user.

## Decisions

## Outcome

`src/` is layered, lowest first: `core/`, `registry/`, `workfiles/`, `adapters/`, `store/`, the
`review/`, `status/` and `work/` services, `commands/` and the entry points. `npm run lint:imports`
refuses an import cycle, type-only imports included, and an import from a higher layer outside the
tests; it replaces the `eslint-plugin-import-x` cycle rule. The two cycles it found are gone: the
projections moved below `db.ts` into `store/projections/`, and `ReviewResult` moved to
`core/outcome.ts`. Modules export only what other modules use, dead code is removed, the status and
ledger-import computation is separate from its reads, and duplicated helpers are collapsed. The
CLI, its output, persisted formats and the build API subpaths are unchanged. Ships in 6.2.0.
