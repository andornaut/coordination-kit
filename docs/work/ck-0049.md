Exports that only tests use become private. Their tests exercise the module through the
interface other modules use, keeping every falsifiable assertion. Internal only.

Source request: ck-0047 follow-up.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-0047-followups): One wrapper, refuse repeats; inject clock, env and hostname in the same major; test via public interfaces (all Recommended)

## Outcome

No module in `src/` outside the public build barrels exports a name that only tests use. Of the
33 such exports in 21 modules, 27 are private and their tests go through the interface other
modules use: `workerHealth` for the child health collector, the `claude channel` handler (which
takes its streams, transcript directory and clock as options in place of `runChannel`), `serve`
for the channel protocol, `diagnoseHarness` for the channel command and server rows,
`codexQueueTransport` for the native queue, `storeSessionStart` for the /clear rotation conflict, a
chained `prepareCompactionCheckpoint` for the checkpoint tail, and `WakeWatcher`, `writeWakeFile`
and the file's JSON for the wake file. Tests state the constants and paths they check (error
classifications, reasons, digest headings, the header limit, the lineage scan interval, the channel
launch command and the result and status file paths) as literals. Two pure units moved to their
own modules, which other code uses: the WebSocket framing to `adapters/codex/websocket.ts`, used by
`rpc.ts` and the test control server, and the native question observation to
`store/codexQuestionObservation.ts`, used by `codexQuestionEvidence.ts`. The child health
collector's page and call bounds are fixed at 10 and 256. Unit cases go from 505 to 506 (the
checkpoint chain is a new case) and contract cases stay at 11. The public build declarations, the
CLI and its formats are unchanged.
