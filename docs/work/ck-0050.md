- One CLI wrapper parses options for the store, `work` and `graph` verbs. Every verb refuses a
  repeated single-value option.
- Functions take the clock, environment and hostname as explicit parameters instead of reading
  them implicitly, including public `build/store` signatures.
- Both are incompatible changes and ship together in one major release.

Source request: ck-0047 follow-up.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-0047-followups): One wrapper, refuse repeats; inject clock, env and hostname in the same major; test via public interfaces (all Recommended)

## Outcome

One wrapper, `verbFamily` in `src/commands/args.ts`, runs the store, `work` and `graph` verbs, and
one parser, `parseOptions`, parses every command. Every command refuses a single-value option given
more than once (exit 2); list options repeat. The wrapper takes exactly the positionals a form
names, refuses a blank value or positional, prints `invalid_FAMILY_options (COMMAND)` for a usage
error and the store refusal code, else `FAMILY_operation_failed`, with a refusal's short reason
after it. `work` verb failures now print `work_operation_failed`.

Library code takes the clock (`Clock`, `() => Date`), the environment and the host name as explicit
leading parameters or context fields; only `bin.ts`, `cli.ts` and `commands/` read the real ones.
Stores, the registry writers, the review, ingest, retirement, the Codex collectors, the file
authority's Git checks, the control socket's home and decision text's host name check take them
explicitly, and the tests pass a fixed clock. Ships in 7.0.0 with the
[upgrade steps](../upgrading.md#coordination-kit-70).
