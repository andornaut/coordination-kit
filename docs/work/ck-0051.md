A channel launched with a conversation that a `/clear` rotated follows the lineage to the role's
current binding. The successor transcript can sit in a different Claude project directory from
its predecessor when the session's working directory is reached through another path, such as a
symlink. The successor search then never finds it, and the channel stays unresolved.

- The successor search covers every project directory, as the predecessor search does, and keeps
  its header limit and once-a-minute rate.
- The review reports a Claude role whose channel status file is missing or names a conversation
  other than its binding.

Source request: Game Coordinator review defect report.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-channel-lineage): Yes, as 6.4.0 before 7.0.0 (Recommended)

## Outcome

`clearSuccessor` searches every project directory under the projects root, with the same header
proof, header limit, exactly-one rule and 16-step channel walk. It reads only `*.jsonl` transcripts
modified at or after the predecessor's own transcript, and the channel still scans at most once a
minute while unresolved. The scheduled review reports each active Claude role whose channel status
file is missing or names another conversation as `channel-unresolved`, and an unreadable one as
`channel-unknown`; `review show` keeps every role's channel status under `native.channels`.
`harness doctor` reports the same cases through `channel_server` codes `status_file_stale` and
`status_file_unreadable` and a new `conversation` field. A running channel rewrites its status
file within a minute of a rebind, so a routine `/clear` does not leave it stale. Ships in 6.4.0.
