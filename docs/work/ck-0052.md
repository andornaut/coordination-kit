`question attach` writes through a store opened read-only and has never recorded anything.
`question reask` needs a native closed-without-answer observation that the code never produces.
Question ownership no longer depends on native evidence, so both are removed,
with the native-evidence code only they use.

Source request: ck-0050 consumer check.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-attach-reask): Remove both at the next major
- D2 (user, 2026-11-25; answers q-ck-0052-version): 7.1.0, the commands never worked

## Outcome

`question attach` and `question reask` are removed with their option and spec entries, their
services (`storeQuestionAttach`, `storeQuestionReask`), their store writers (`linkNativeQuestion`,
`reaskNativeQuestion`) and the helpers only those writers used (`nativeQuestionIdentity`,
`sameNativeQuestion`, `requireNativeProof`, `nativeQuestionUnused` and the
`closed-without-answer` proof status). Both now exit 2 as unknown commands. `question reconcile`,
its bounded evidence reader and observation, `question close-legacy` and the review's native
survey are unchanged. The `question.native-linked` and `question.native-reasked` projections and
file-record routing stay, so an existing store or journal that contains them rebuilds the same
native identity and attempt. Ships in 7.1.0.
