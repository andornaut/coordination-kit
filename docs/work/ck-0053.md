Since `question attach` was removed, nothing records a native question link, so
`question reconcile` always reports the question unlinked unless an older store holds a link.
No path depends on it to close a question. Remove the command and the native-evidence code only
it uses; old events keep replaying.

Source request: ck-0052 follow-up.

## Decisions

- D1 (user, 2026-11-25; answers q-ck-reconcile): Remove it as 7.2.0 (Recommended)

## Outcome

`question reconcile` is removed with its spec entry and its service (`storeQuestionReconcile`),
along with the code only it used: the bounded evidence reader and observation modules
(`codexQuestionEvidence.ts`, `codexQuestionObservation.ts`), the `evidence()` helper, the
`questionEvidence` context port, `NativeQuestionProof`, `requireOwnQuestion` and the
`decisionRecord` marker reader. It now exits 2 as an unknown command. The recorded native identity
and attempt stay on `question list` and `session start` output and on the pending-question wake
blocker, since an existing store or journal can still hold them. The `question.native-linked` and
`question.native-reasked` projections and file-record routing stay, and the replay test now also
checks the replayed identity on the wake blocker. `question close-legacy`, the review's native
survey and `collectQuestionState` are unchanged. Ships in 7.2.0.
