With `verbatimModuleSyntax`, `import { type A }` still loads its module at runtime, while
`import-x/no-cycle` treats it as type-only, so a runtime cycle closed by one passes lint. ESLint
enables `@typescript-eslint/no-import-type-side-effects`, and those imports become `import type`.

Source request: Game Coordinator, relaying Archie Tech under `gc-0029`.

## Decisions

- D1 (user, 2026-11-26; answers q-ck-type-side-effects): Yes, as 7.2.1 (Recommended)

## Outcome

ESLint enables `@typescript-eslint/no-import-type-side-effects` over `src/`, `scripts/` and
`tests/`. The two imports whose specifiers were all inline types, in `src/commands/compaction.ts`
and `src/store/files/records.test.ts`, are now `import type`. Released in 7.2.1.
